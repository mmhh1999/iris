# EXP0037 预先登记：真实房间多时刻光斑预测（Cali-HDR coda_334）

2026-09-27 写定，任何留出时刻的预测结果出来之前。**判定规则出结果后不得修改；要改须另立实验编号并写明理由。**

## 要回答的问题

在真实房间里，"星历 + 一个标定朝向"（C）是否比"逐时刻从图像估计太阳方向、再按时间外推"（B）更能预测**未见时刻**的光斑位置？

这是 T11 判定规则 R2 在真实数据上的几何部分。它只检验光照几何，不涉及材质。

## 数据

- 房间：Cali-HDR `coda_334`，匹兹堡，40.458N, 79.933W（EXIF GPS）。
- 设备：RICOH THETA Z1 全景，每个时刻 9 档包围曝光。
- 相机：同一天内三脚架固定。各时刻边缘图互相关，朝向偏移为 0，分辨率 0.21°。
- 主数据：2023-07-06（9 个时刻）。
- 重复：2023-06-25（9 个时刻）。
- 时间取 EXIF 里的 GPS UTC 时间戳。
- 只用 JPG，未解压 RAW。亮度只用于检测光斑，不做辐射度量。

## 几何（在看任何预测结果之前固定）

1. **调平**：取每天一个参考时刻（07:56），用透视切片里接近竖直的线段估计真实"上"方向（EXP0037-L）。2023-07-06 的倾斜为 0.64°，中位残差 0.16°。
2. **房间**：
   - 相机高度记为 1 个单位，整个几何按此定尺度；尺度不影响光斑在全景里的位置。
   - 按曼哈顿假设建模：窗墙、右墙、左墙和地板。
   - 墙面位置用标注的地板–墙交线点拟合。
3. **窗洞**：
   - 窗洞 = 标注的墙面开口矩形，外加一个进深 r 的窗套（隧道）。
   - r 只用训练时刻拟合，候选值 {0, 0.05, …, 0.40} 个相机高度，B 与 C 各自拟合。
   - 窗框的十字中梃不建模，B 与 C 同等受影响。
4. 标注存为 JSON 冻结（`research/evidence/EXP0037/annotation_*.json`）后，才开始任何留出评估。

## 光斑检测（与预测无关）

- 用曝光档合成近似相对辐亮度：取每个像素最长的未饱和曝光，除以曝光时间。
- 评估区域：墙面和地板像素，排除窗洞本身，只取仰角 < +10° 的部分。
- 在这个区域内对 log 亮度做 Otsu 阈值，再做形态学清理。
- 检测只看图像，不看任何太阳方向。

## 对照组

| 组 | 太阳方向 | 自由度 |
|---|---|---|
| C | pvlib 星历（GPS + UTC）+ 相机朝向 ψ；ψ 在训练时刻上搜索，使光斑 IoU 最大（多个训练时刻联合） | 1（ψ）+ r |
| B | 每个训练时刻单独搜索 (方位, 仰角)，使 IoU 最大；留出时刻用 (方位, 仰角) 对时间的最小二乘直线外推 | 每时刻 2 + r |
| Oracle-方向（上限诊断） | 在留出时刻直接搜索最优方向 | 2（不计入判定） |

## 切分（每天各做一次）

- **外推**：训练 = 当天最早的两个有光斑的时刻；留出 = 其后所有有光斑的时刻。
- **内插**：训练 = 第一个和最后一个有光斑的时刻；留出 = 中间的时刻。
- "有光斑的时刻" = 检测到的光斑面积 > 评估区域的 0.2%。检测结果冻结后再定切分。

## 指标

- 留出时刻的光斑 IoU（全景像素，按 cos 仰角加权）。
- 光斑质心的角误差。
- 各组留出方向与 Oracle-方向之间的夹角（诊断用）。

## 判定规则

- **R2-real**：主数据（2023-07-06）外推切分下，C 在留出时刻上的平均 IoU 比 B 高 ≥ 0.1；并且在重复数据（2023-06-25）上方向一致（C > B）。
- 如果 Oracle-方向本身的 IoU < 0.5，说明几何模型太差，不解读 R2-real，只报告几何失败。
- 结果无论正负都写进 `EXPERIMENTS.md`；负结果同时写进 `FAILED_IDEAS.md`。

## 事先说明

- 已经在全景缩略图上定性看过各时刻光斑的大致位置，用于判断这份数据是否可用。这无法避免，特此说明。
- 切分规则和判定规则都在任何定量预测之前写定。
- 真实数据的主要风险是几何误差，包括窗套进深、十字中梃和调平。B 的每时刻两个自由度可以吸收一部分几何误差，C 的一个自由度不行。**因此 C 未必占优。**
